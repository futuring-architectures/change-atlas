## Curated excerpt

> *Over time, we will treat “humans had to read this to be comfortable” as a smell in our code generation pipeline, or as an explicit, expensive trade-off reserved for truly mission-critical subsystems. A natural outcome of this shift is a “code reading coverage” metric, tracked much like test coverage. What fraction of production code has actually been read by humans, partly as a safety signal, and partly as a metric teams deliberately and safely work to drive downward toward an asymptote.*

## Atomic claims

### Claim 1

Human code reading will become an explicit, expensive exception reserved mainly for mission-critical subsystems.

- Classification: `prediction`
- Scope: Enterprise software produced by advanced coding agents.
- Date relevance: Forecast published 2026-02-09.
- Qualification: The transition depends on model reliability, regulation, liability, testing, observability, and organizational risk tolerance.

### Claim 2

Teams may track code-reading coverage as both a safety signal and a metric they intentionally drive downward.

- Classification: `prediction`
- Scope: Governance metrics for AI-generated production code.
- Date relevance: Forecast published 2026-02-09.
- Qualification: Lower reading coverage is safe only if trustworthy replacement mechanisms provide equivalent or better assurance.
